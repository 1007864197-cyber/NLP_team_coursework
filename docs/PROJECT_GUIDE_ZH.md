# 餐厅客服项目理解与使用指南

## 这个项目在做什么

它实现第 1 号题目：顾客向一家虚构餐厅提问，软件用自然的英语回答，并能在连续对话中保留饮食偏好和预算。主要语言是 Python；网页由 HTML、CSS、JavaScript 构成。Python 后端负责 NLP 和回答，网页负责让用户操作。

第一次运行请看项目根目录 README.md 或双击 START_WINDOWS.bat。安装依赖需要联网，安装完成后本地运行无需模型账号和 API 费用。网页地址为 http://127.0.0.1:8765 。

## 为什么它属于 NLP

顾客输入的是自由文本，系统要把文字转成可以比较的数值表示，识别问题对应的意图，从资料中选取回答，还要从文字里提取饮食偏好和价格上限。

TF-IDF 会给词语分配权重：某个词在一条问句中出现、又不是每条问句都有，它就更可能帮助区分这条问句。系统把输入和示例问句转换成向量，使用余弦相似度比较接近程度，再选取对应的餐厅资料。基础方法使用词特征，改进方法加入相邻词组和字符片段。字符片段有助于处理部分拼写错误，但不等于真正理解所有语义。

对话状态保存当前饮食条件、预算和上一轮推荐。用户说“Make it vegan instead”时，系统更新之前的条件；“Which is the cheapest”则需要结合已有推荐来回答。状态机和条件提取属于规则方法，不要在展示中把它说成经过训练的大语言模型。

项目还训练了真正的监督式意图分类模型。训练语料包含 19 类、380 个独立原始问句组，先划分训练与开发集，再只对训练集做礼貌前缀增强，防止同一句的变体进入两边。训练脚本实际比较逻辑回归、朴素贝叶斯与线性支持向量机，按开发集表现选择模型与拒绝阈值。最终评估数据不参与这个过程。数据是为项目编写的合成英语语句，应如实解释其局限。

回答下方可以展开依据，便于解释系统为什么返回这段内容。分类分数、检索相似度或规则分数都不是“正确率”，也不是“回答有百分之多少概率正确”。

## 代码怎么读

建议按 data → restaurant_bot → app.py → static/app.js 的顺序。先了解餐厅资料和示例问句，再了解文本特征和检索，之后看对话条件如何更新，最后看网页怎样调用后端。

修改餐厅设定时同时检查菜单、FAQ 和评估数据。不要只修改网页上显示的名称，造成回答与菜单不一致。代码中的注释解释方法和关键限制。readme.txt 列出了外部库，requirements.txt 用于安装。

## 可以展示的功能

1. 问餐厅营业时间或地址，展示直接问答。
2. 连续询问素食推荐、改成纯素、设置预算、选择最便宜的菜，展示上下文。
3. 用不同说法和一个拼写错误询问同类问题，展开检索依据。
4. 输入无关问题，展示系统如何承认范围限制并引导回来。
5. 筛选网页菜单、导出聊天记录、重新开始对话。
6. 解释基础方法与改进方法的差别，展示实际评估结果和失败案例。

英语是当前支持的输入语言。菜品与联系方式都是虚构示例，系统不会创建真实订位。过敏问题应提示联系餐厅确认，菜单标签不能保证没有交叉接触。

## 怎么理解评估

在项目文件夹中用已安装依赖的 Python 运行：

```text
python -m unittest discover -s tests -v
python evaluation/run_evaluation.py
```

前者检查功能是否满足预期，后者比较两个检索方法，并输出实际测量结果。不要只挑最高分；保留原始逐条结果、说明样本数、指标含义和失败原因。评估语句是人为编写的小样本，不能代表真实顾客的全部语言习惯。若看过评估问题后据此修改模型，该集合就应当按开发评估集描述，再额外收集新问题做独立测试。

报告应区分检索表现、完整对话功能和界面测试。一个检索准确率不能证明用户满意度，也不能证明整个系统任何情况下都能正确回答。

## 小组报告还要填什么

报告中的 [Lab Class]、[Team Number]、[Member names in PinYin] 和成员职责需要填写。分工应反映你们实际做过的工作。建议每人选择一个能独立解释和改进的部分，例如资料与对话设计、NLP 方法、网页交互、评估与报告。团队人数和分工未确定前，不要把建议写成已经完成的经历。

团队报告最多四页。个人报告每人一页，个人贡献占 coursework 总分的 40%。报告应与最终代码和重新运行后的结果保持一致。

## 为了展示得更好

至少安排三位成员发言，并且每人能解释所负责的代码或方法。演示前在实际展示用电脑上启动一次，保存一份对话导出记录备用。展示不只演示成功案例，也说明一条失败案例及改进方向。可以考虑后续扩充独立用户问句、改进复杂否定与指代解析，或比较语义向量与当前词汇方法；未实现的部分应写入 future work。
